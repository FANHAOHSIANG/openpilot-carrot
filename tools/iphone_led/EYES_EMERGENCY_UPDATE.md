# Carrot LED 眼睛動畫與急煞提示

Android 0.1.5（versionCode 6）／iPhone 0.22（build 22）。C4 橋接及金鑰不變，只需更新 App。

## 六款眼睛

晶亮眨眼、靈動眼、惡魔眼、螺旋眼、火焰眼、機甲眼。包含漸層虹膜、高光、瞳孔移動及連續閉眼／張開；這些是參考風格重新製作的素材。快捷頁可點選，文字與動畫頁可選顏色。

- iPixel 64×16：預設開啟「iPixel 原生平順動畫」。素材為 20 fps、1.6 秒循環；只在內容或顏色切換時上傳，播放由屏幕執行，不需手機持續傳每一格。
- 使用暫存 slot 0，不寫入屏幕 ROM。每個 GIF 不超過 8 KiB，單一上傳視窗，等待屏幕 ACK。
- BLE 可寫長度至少 100 bytes 才使用原生 GIF。其他尺寸、較小 MTU，或關閉原生開關時，使用目標 5 fps 相容播放；iPixel 相容模式是單色，LOY 為四層顏色。不是所有控制板都支援相同 GIF 功能。
- 素材 fps 不代表已量測的實體 fps。首次上傳及切換仍有 BLE 傳輸時間；車況、清屏會取代尚未開始的待送內容，已開始的封包需完成後才能送下一個命令，不能保證零延遲。
- 車況提示優先於眼睛，事件解除恢復眼睛；清屏會取消所有顯示並停用自動車況。自動車況開啟但資料失效時仍嘗試清屏。

## 急煞定義

| 條件 | 設定 |
|---|---|
| 檔位 | D 檔 |
| 車速 | 至少 20 km/h |
| 減速度 | 至少 4.5 m/s²，等同 C4 aEgo ≤ -4.5 m/s²（約 0.46 g） |
| 確認 | 持續至少 0.3 秒，至少三筆有效車況；樣本間隔不可超過 0.5 秒 |
| 雙黃燈／煞車踏板 | 都不是必要條件；依實際減速度判斷 |
| 顯示 | 先顯示「前方塞車」，再與「減速中」每 2 秒交替；兩項原有文字、顏色與效果可獨立編輯 |
| 保持 | 自觸發起至少 6 秒；若仍持續急減速則延長 |
| 解除遲滯 | 加速度高於 -2.0 m/s² 或車速低於 3 km/h，持續 0.5 秒後解除急減速狀態；仍完成剩餘保持時間 |
| 立即取消 | 離開 D 檔、資料失效、樣本間隔超過 0.5 秒或時間倒退；回到當下車況規則 |

此為自訂後窗 LED 提示門檻，不是原廠緊急煞車燈標準，不會控制車輛煞車或原車雙黃燈。4.5 m/s² 約相當於每秒降低 16.2 km/h；短促抖動不會觸發。一般踩煞車仍立即顯示「減速中」，一般動能回收沿用 ≥5 km/h、≤-0.5 m/s² 持續 0.3 秒的門檻；若回收／自動煞車本身達到急煞門檻也會觸發。以上依 C4 實際提供的加速度資料運作，並非辨識前方是否真的塞車。

快捷及樣式頁標題由「急煞雙黃燈」改成「急煞提示」，儲存代號保留，所以舊自訂內容仍在。開啟自動車況時，真正急煞會結束手動車況預覽並優先顯示；手動關閉自動車況／清屏後不會擅自重新啟用。

## 更新與驗證

Android 覆蓋安裝同簽章 APK；iPhone 解壓完整 ZIP，執行 `xcodegen generate`，沿用兩個 Target 的原開發團隊及 Bundle ID，再 Run。不要只替換 Swift 檔，本次有新增 GIF 資源與規則檔案。

離線驗證包含兩平台共用的 291 筆情境（一般回收、邊界速度／減速度、瞬間尖峰、長時間急煞、6 秒保留、換檔、資料缺失）、六個 GIF 與 pypixelcolor 的完整封包雜湊比對、GIF 解碼及幾何／資源驗證。Android APK 編譯及簽章檢查在本機完成；iPhone 完整 App／extension 與模擬器畫面由 GitHub Actions 驗證。實際屏幕原生 GIF 解碼、BLE 延遲及車機背景行為仍需裝置驗證。

安裝後先在停車狀態手動預覽眼睛及急煞文字。不需為了測試 LED 而在道路上刻意急煞。
