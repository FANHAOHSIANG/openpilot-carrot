# iPhone 0.26：LOY 局部更新與合併傳送

使用者回報 0.25 的圖案仍不夠滑順。0.25 每格先清整屏、再逐個色層傳送；本版改為比較前後畫面，只傳變動像素，移動後的舊位置明確塗黑，不把零位元誤當成擦除。

- 眼睛、胡蘿蔔車開屏及既有 LOY 文字／圖案都使用局部更新。相同畫格不重送。
- 裁切變動區域，依資料量選擇矩形或分列編碼，再把多個繪圖 TLV 合併到最多 960 位元組的封包。每次 BLE 寫入上限 244 位元組，仍服從手機實際可寫入長度與流量控制。
- 動畫維持最高目標 20 fps 與原播放時間；忙碌時跳過舊格。減少不必要的畫面狀態通知，避免每格重建相同 UI。
- 持續播放時至少每兩秒重新覆蓋完整畫面一次，修復可能的丟包殘影；這次覆蓋以彩色與黑色點陣完成，不先把整屏清空。
- 斷線、電源切換及其他直接繪圖會重設畫面估計。收到有效的拒絕回覆時重新同步；若屏幕回覆「不支援」，改用逐命令傳送。

這仍是手機即時繪圖，不是屏幕內建 GIF 播放。本版未在使用者的 LOY PLAY 96×16 實機確認，不能把目標 fps、送出完成或協定回覆當成屏幕實際顯示速度。iPixel 原生 GIF 路徑沿用既有實作。

## 安裝

下載完整 `CarrotLED-iOS-0.26-Source.zip`，解壓後進入 `iphone_led_lan`，執行 `xcodegen generate`，在 Xcode 沿用原本兩個 Target 的 Personal Team／Bundle Identifier，再 Run 到 iPhone。保留舊 App 與設定。

本次更新 iPhone；Android 下載版仍為 0.1.8。C4 已有可用橋接者不需重裝。完成後用同一款眼睛動畫比較，再確認文字切換、清屏及關屏。

## 驗證

`LoyCanvasTests.swift` 以獨立的屏幕命令解碼器重建每格畫面，涵蓋不同寬高、非 8 的倍數寬度、配色變更、重複與跳格、黑色擦除、重連後全畫面同步、丟包後定期修復、逐命令退回，以及 64×16／96×16 全部 48 格開屏素材。傳輸量比較包含週期性完整覆蓋，屬程式碼計算，不是硬體量測。

15,270 項局部更新／合併封包／畫面重建檢查通過。48 格開屏素材的計算結果：

| 素材 | 協定資料總量（含封包） | BLE 寫入次數（舊上限 180／新上限 244） |
| --- | --- | --- |
| 64×16 | 10,916 → 3,441 位元組 | 158 → 27 |
| 96×16 | 14,506 → 3,771 位元組（減少約 74%） | 178 → 28 |

這些數字只對應開屏素材，不代表所有眼睛動畫都有相同降幅；也不含系統／空中封包開銷。小 MTU 裝置的寫入次數會更多。

完整 App、Live Activity extension、既有車況／開屏／iPixel 檢查與模擬器啟動由 GitHub Actions 驗證。

## 協定依據

同系列設備的實測協定記錄：[ysmatrix protocol §3、§7](https://github.com/thorbengrosser/ysmatrix/blob/main/docs/protocol.md)。其多 TLV 封包與即時繪圖觀察用作本版編碼依據，不代表所有 LOY 控制板均已驗證。
